# Deferred — wanted, deliberately not now

The gap between "never" and "now". Three places already say something about work that does not
exist yet, and each says a different thing:

| | |
|---|---|
| Your design doc's non-goals | **never** — absences that are decisions, not oversights |
| **this file** | **not yet** — wanted, out of scope for the current milestone |
| Your tracker | **now** — filed, scoped, someone will start it |

**An entry names the change and what would have to be true to admit it. No dates, no ordering, no
priority.** That is not a style preference. A ranked list here becomes a second build order
competing with the tracker, drifts from it, and rots — and your tracker is already the ranked list.

**If it has a shape and someone would plausibly start it this month, it is a tracker issue instead**,
staged through `issues.md` if it needs root-causing first. An entry leaves this file the moment it
is filed, replaced by nothing: the tracker carries it from then on, under the same rule that governs
`issues.md` — a filed item lives in exactly one place, and a pointer to it is fine while a
restatement of it is not.
