# Meetings

One file per joint working session, `<YYYY-MM-DD>.md`, written by `/make-agenda` and stamped
`Status: executed` by `/end-meeting`. Exactly two states, `prepared` then `executed`, because only
those two skills write to it — at the two ends.

**No owner in the path.** A meeting belongs to everyone in it, the same reasoning that keeps
`work/archive/` shared.

**Not union-merged, deliberately.** One file per date means two people cannot append to the same
one, which is the condition union merge exists for.

**The split between deciding and executing is the point.** A meeting that edits files as it goes
leaves half-applied decisions when it overruns, and a half-applied meeting is indistinguishable
from a finished one to the next session.
